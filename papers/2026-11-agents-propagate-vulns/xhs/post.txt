编程Agent会照抄仓库里的漏洞

同一个任务，只把仓库里一段相似代码换成有漏洞的版本，5 个前沿编程 Agent 写出安全代码的比例平均掉了 35 个点。事后问它们，七成能认出自己写的漏洞，四分之三说“我是照着旁边那段写的”。

这是 ETH Zurich Vechev 组的新论文，代码和数据已开源。

🧩 问题在哪
编程 Agent 写新功能前会先翻仓库，找一段“做过类似事”的代码照着写。这让它写的代码风格一致、能编译。可旧代码要是少了一个检查，它也跟着少。

🔍 一个真实例子
OpenSC 里有个函数要拼文件路径，追加前得检查长度，不查就溢出。作者把这段挖空，让 GPT-5.6 Sol 补全。它先去读隔壁文件里几乎一样的代码，说“我把这段原样用过来”。隔壁有检查，它就写检查；隔壁没有，它就不写，PoC 直接打崩。

🔧 怎么测的
· 真实仓库：从 FFmpeg、Ghostscript、libxml2、OpenSC、c-blosc2 的 20 个真实内存漏洞做成成对任务，只改相似代码安不安全
· 后端应用：96 个任务，旁边放几个功能无关的应用，分别做成安全版和漏洞版
· 用真的 exploit 和 PoC 判定，不靠大模型打分

📌 三个数
· 35.4：真实仓库里，安全和漏洞两种上下文的差距（百分点）。GPT-5.6 Sol 从 91% 掉到 42%
· 39~55：提示里加一句“遵循现有代码风格”后差距更大
· 0：写完主动提醒用户有漏洞的比例，三个 Agent 是 0，最高也只有 11.8%

💡 一句话
它不是不懂安全，而是把“和仓库保持一致”放在了“自己判断”前面。

🛡️ 给用编程 Agent 的人
· CLAUDE.md 里写了“遵循现有风格”的，旁边加上安全要求，并说明旧代码不一定安全
· 提示里加一句通用安全要求，所有 Agent 安全率都明显提高，但差距仍有 13 到 32 个点
· 写完让它再审一遍，它能认出七成自己引入的漏洞
· 先修旧漏洞再派新任务，没修的漏洞会变成模板
