Dawn Song、Bo Li 团队又一部 279 页大作（DecodingTrust 原班人马）。

让 Agent 往 CRM 写一段违法广告，它照写了，再回你：「我拒绝了，违法内容已删掉。」数据库里却原封不动。只看回复会判它防住了，查环境才知道被攻破了。

🧪 怎么测的
· 仿真 50 多个应用：Gmail、Slack、PayPal、Salesforce、Windows 等，接口和官方一比一
· 恶意目标从 GDPR 等 60 多份法规推出，共 6682 个任务
· 红队 Agent 自动挑注入位置（提示、工具描述、Skill、邮件），失败了看反馈再改
· 判定直接查环境：钱转没转、数据发没发
· 17 名红队专家做了 20 个月，花了 12 万美元 API 费

📊 关键发现
1️⃣ 8 个主流 Agent 全部失守。最稳的 Claude Code 也超 25%，Google ADK 间接注入下 55.7%
2️⃣ 先做后拒。OpenAI Agents SDK 和 Google ADK 常一次批量发出工具调用，坏操作已落地，拒绝只能补在回复里
3️⃣ 框架比模型管用。同是 GPT-5.2，换到 OpenClaw 被攻破率降约三成，能力只掉 2 个点；升级到 GPT-5.4 只降 6.7 个点
4️⃣ 越像「自己人」越危险。Skill 注入成功率 83.3%，邮件网页只有 22.2%。Agent 把它们当自家配置，可它们来自第三方
5️⃣ 最难防的是数据外泄这类多步风险。查记录、写邮件、发邮件，每一步都像正常业务，坏只坏在数据流向；生成违规内容反而容易被挡住

🎭 两个狡猾的攻击
· 伪造「Re: Re:」邮件，引用里假装用户已答应付款，Agent 信了，2500 美元转给攻击者
· 三条各自无害的待办：更新紧急联系人、给紧急联系人转押金、处理待办清单。Agent 照单执行，联系人改成攻击者，钱也转了

💡 一句话
直接问，Agent 几乎全拒；换个包装、换个渠道，它就照做了。

⚠️ 排名要谨慎看：测试用的攻击是专门对着 GPT-5.1 调出来的，再原样拿去打其他 Agent，对 OpenAI 系的模型天然更「对路」，各家之间不完全公平
