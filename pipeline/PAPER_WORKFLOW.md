# /paper 工作流：论文 PDF → 公众号草稿箱

输入：论文 PDF 路径。输出：公众号草稿箱中一篇图文草稿。
凭据在仓库根 `.env`，绝不打印。发布动作永远由用户在公众号后台手动完成。
所有 Python 命令用仓库的 `.venv/bin/python` 执行。

## 步骤

### 0. 查重（强制，第一步，绝不跳过）

处理任何论文前，先确认它**没被推送过**。不能只匹配标题——**arXiv 版和最终出版版的标题常常不一样**，作者也可能改题。用多个信号交叉查：

- **arXiv 号**：`grep -rl "<arxiv-id>" papers/*/article.md papers/*/*.json`
- **英文标题关键片段 + 作者名 + 机构**：`grep -rliE "<title 片段>|<第一作者>|<通讯作者>" papers/*/article.md`
- **独特内容词**（论文特有的系统名/数据集名/术语，别用 SkillsMP、GPT 这类高频词，会误报）
- 再 `ls papers/` 眼扫一遍同主题目录，逐个看 `title_en` 确认没有同一篇的不同标题版本。

任一信号命中就人工确认是不是同一篇（同作者+同核心贡献=同一篇，即便标题措辞不同）。确认是新的才往下走；拿不准就问用户。

### 1. 建目录

- slug 规则：`YYYY-MM-<论文短名小写>`（如 `2026-08-malskillbench`）
- `mkdir -p papers/<slug>/assets` 并复制 PDF 为 `papers/<slug>/paper.pdf`

### 2. 读论文

- 用 Read 工具直接读 `paper.pdf`（分段读完全文），掌握：问题、挑战、方法、实验结果、局限。
- 提取元信息：英文原题、作者与机构、发表 venue、arXiv 链接、代码仓库链接（通常在摘要或脚注）。

### 2.5 判定论文类型（决定后续所有模板）

读完先判类型，它一次决定四件事：**分析侧重、文章结构、图片选择、封面点缀色/标签**。
排版骨架对所有类型统一（保持公众号视觉一致）；只有强调色和上述四点按类型切换。
`kind` 值写进 front matter（见第 4 步），封面渲染和排版会自动跟随同一套同色系配色。

| kind | 判别特征 | 分析侧重 | 结构骨架 | 图片选择 | 封面色/标签 |
|---|---|---|---|---|---|
| **survey** | 综述/SoK，梳理大量文献、提分类框架 | 全景框架 + 交叉发现 + 系列串联（横向铺开） | 导读→为何需要新视角→框架图→逐部分展开→量化发现→点评 | 分类树/框架图 + 覆盖热图/统计图 + 关键对比表 | 青绿·综述解读 |
| **benchmark** | 提出一个基准/数据集来评测 | 构建方法的严谨性 + 跑出的反直觉结论 + 和同类基准的区别 | 导读→和同类的区别→构建流水线→跑出的结论→点评 | 构建流水线图 + 主结果表 + 反直觉对比图 | 天蓝·基准解读 |
| **method** | 提出新方法/系统解决一个具体问题 | 痛点→**一句话核心洞察**→方法(为什么这么设计)→证据(主结果+**那张消融**)→边界 | 导读→痛点→核心洞察→方法→实验(主结果+消融)→点评 | 架构图 + 动机案例图 + **证明洞察成立的消融/对比表** | 浅紫·方法解读 |
| **empirical** | 实证/测量，用真实数据坐实一个风险 | 数字冲击力 + 方法论严谨(含伦理设计) + 反直觉发现 | 导读→背景→测量方法→数据发现→点评 | 威胁模型/杀伤链图 + 核心数据图 + 反直觉发现图 | 琥珀·实测解读 |
| **system** | 落地一个真实系统/平台/工具 | 工程取舍 + 规模化数据 + 实战战果 | 导读→问题→系统设计→实战战果→点评 | 系统架构图 + 主结果表 + 成本/规模化图 | 珊瑚·系统解读 |

- 判不准时按"论文最想让你记住的一句话"归类：讲"领域全貌"→survey；讲"一个巧思"→method；
  讲"一批数据说明一件事"→empirical/benchmark；讲"我造了个能跑的东西"→system。
- **类型只靠封面右上角标签 + 点缀色体现，绝不写进标题文字**（不要出现"综述类：""方法类："这种前缀）。
- **「启发与点评」节所有类型都保留**（现在的三段式：对研究者 / 对从业者 / 一句系列串联的观察），
  只是侧重不同：survey 偏选题地图，method 偏"这个巧思能学到什么"，empirical 偏"数据对你意味着什么"，
  system 偏"落地价值"，benchmark 偏"评估方法论的启发"。
- **method 类是重点**：不要写成模块流水账，必须提炼出"一句话核心洞察"用引用块（`> `）单独拎出来，
  并重点放大"证明洞察成立的那张消融/对比图"（如 PRAXIS 去掉上下文裁决 F1 从 87% 崩到 24.7%）。
- **引用块 `> `**：核心洞察、定理、关键定义都用它高亮（渲染成左边框强调色块）。

### 3. 提图

- `.venv/bin/python scripts/extract_figures.py pages papers/<slug>/paper.pdf papers/<slug>/pages`
- 用 Read 目视各页 PNG，选定：1-2 张核心架构/方法图、1-3 张关键结果图。
- 写 `papers/<slug>/figspec.json`（bbox 单位为 PDF point；从 150dpi 页面图的像素坐标换算：`pt = px ÷ 150 × 72`），架构图 out 到 `assets/fig/`，结果图到 `assets/result/`。
- `.venv/bin/python scripts/extract_figures.py crop papers/<slug>/paper.pdf papers/<slug> papers/<slug>/figspec.json`
- `.venv/bin/python scripts/extract_figures.py header papers/<slug>/paper.pdf papers/<slug>/assets/header.png`

**图表完整性检查（强制，不可跳过）**：用 Read 工具**逐一**打开每一张裁剪产物（含 header），
按下面的清单逐张核对，任何一条不满足就调整 bbox 重裁并重新 Read，直到全部通过：

- **无截断**：图/表的四条边都在画面内，没有半个字、半行、半列、半个坐标轴被切掉。
  特别检查顶边和底边——多栏论文的图常常上边贴着正文，容易切掉标题行或第一行元素。
- **题头完整**：`header.png` 必须包含论文标题的**全部行**和**全部作者行**。
  很多论文作者排成两行或多行（如 3+2），只截到第一行是最常见的错误；
  用 `get_text("blocks")` 查出作者区块最大的 y1，bbox 底边取"该 y1 + 4pt"再到 Abstract 上沿之间。
- **纯图无杂质**：不含原文的图注/表注文字（图注由我们用中文另写）、不含相邻栏的正文、不含正文段落。
- **表格完整**：表头行、所有数据行、最右一列都在内，没有被切掉的单元格。
- **定位辅助**：拿不准边界时，用 `page.get_text("blocks")` 或 `page.get_drawings()` 打印
  目标区域的文本块与图形 bbox，据此定 bbox，不要凭页面缩略图估。

只有当每一张图都通过上述清单，才能进入下一步。

### 4. 写文稿

**深度要求（强制，最重要的一条）**：解读要"深"，不是更长，而是讲透。写之前和写完都对照这六条：

1. **讲机制，不止讲结论**。每个核心概念、每个发现，都要讲清"为什么会这样、通过什么因果链导致后果"。
   只报"X 占 73%""F1 涨了 0.1"是浅的；要说清 X 为什么发生、它具体如何扭曲结论。数字是证据，机制才是内容。
2. **优先用论文里的具体案例**。复述论文给的真实样本、具体例子、具体数字（那条推文、那个 CVE、那张消融表的崩盘数字），
   而不是自己抽象概括。具体 > 笼统；一个好例子胜过三句"这很重要"。
3. **深挖 2-3 个最有信息量的点**，其余快速带过。宁可少讲、讲透，也不要每个点都浅尝辄止地平铺。
   问自己：这篇论文最反直觉、最颠覆认知的是哪 2-3 件事？把火力集中在那里。
4. **呈现 nuance 与反例**。把论文自己的 caveat、反直觉的反结果、诚实的"我们没能证明 X"也写出来。
   这恰恰是深度和可信度的体现，不要只挑最耸动的讲。
5. **每个发现接一条"所以呢"**。从发现连到具体后果（对研究者/从业者/读者意味着什么），形成因果闭环，别悬在半空。
6. **实验/消融要讲清"证明了什么、排除了什么"**。不是复述数字，而是解释这个实验设计为什么能坐实（或推翻）某个结论。

自检：写完通读一遍，问"读者读完能不能复述出至少两个'为什么'（机制）和一个具体案例？"答不上来就是写浅了，回炉。

- 按 `templates/article_template.md` 的结构写 `papers/<slug>/article.md`，
  **章节骨架和分析侧重按 §2.5 判定的 kind 走那一行**。
- front matter 加 `kind:` 字段（survey/benchmark/method/empirical/system），
  排版强调色会据此自动切换（与封面点缀色同色系呼应），默认 survey。
- 叙事线：读者视角——整体干什么 / 解决什么问题 / 领域挑战 / 怎么做 / 结果如何 / 有何启发。
- 核心洞察 / 定理 / 关键定义用引用块高亮：整段以 `> ` 开头即渲染成左边框强调色块。
- **两级强调**（别标太多，否则失去重点）：
  - 一般重点用 `**xxx**` → 类型强调色粗体（随 kind，如基准=蓝、方法=紫）；
  - 最重要的发现/金句用 `==xxx==` → **红色加粗**，全篇节制在 1-3 处，只留给最该被记住的那句。
- 图插在对应章节，图注为中文、格式"图N：说明"。
- 「启发与点评」结合软件供应链安全领域上下文，写观点不写套话。
- title 中文 ≤64 字；digest ≤120 字；highlights 恰好 3 条、每条 ≤14 字。
- **去 AI 味（用户明确要求）**：正文和图注禁用破折号"——"（改用冒号、逗号或拆成两句；
  排版自动加的图注前缀"— "不算）。写完后 `grep -c "——" article.md` 自查，必须为 0。
- **安全术语按业界惯例（用户明确要求）**：one-day/N-day 写 `1day`（或 1-day），zero-day 写 `0day`，
  不要意译成"一日/零日"；CVE、RCE、POC、MCP 等固定术语保留英文/数字写法，不硬翻中文。
  写完 `grep -n "一日\|零日" article.md` 自查应为空。
- front matter 加 `collection:` 字段（不参与排版，纯提示）：从公众号已预设的合集中选一个，
  用户发布时照此手动勾选（草稿 API 不支持设置合集）。合集清单：
  「AI Agent 安全」（恶意 Skill、提示注入、MCP、Agent 控制面）；
  「恶意包与威胁情报」（PyPI/NPM 恶意包检测、测量、情报聚合）；
  「供应链攻击与防御」（攻击机理、事件复盘、防御机制、SBOM）；
  「开源与安全测量」（大规模实证研究、基准测评）。

### 5. 封面

- `.venv/bin/python scripts/render_cover.py --title-zh "<中文短题>" --title-en "<英文原题>" --venue "<venue>" --kind <类型> --out papers/<slug>/assets/cover.png`
- `--kind` 用 §2.5 判定的类型（survey/benchmark/method/empirical/system），封面点缀色与标签随之切换。
- 用 Read 目视封面，文字溢出则缩短标题重渲。

### 6. 排版 + 发布

- `.venv/bin/python scripts/render_article.py papers/<slug>`
- `.venv/bin/python scripts/wechat_publish.py papers/<slug>`
- 成功后告知用户去 公众号后台 → 内容管理 → 草稿箱 查看。

### 7. 修改重发

- 用户改完 `article.md` 后说"重新发布"：只重跑步骤 6 两条命令（`publish.json` 已有 `draft_media_id`，会走 `draft/update`，不产生重复草稿）。

## 失败恢复

- 每步产物都在 `papers/<slug>/` 内，从失败步骤继续，不从头跑。
- 40164 = IP 白名单失效，提示用户更新（脚本报错信息里有指引）。
- **`JSONDecodeError` / 返回 501 HTML（waf.tencent.com）= 微信 WAF 拦了正文**：文章里含攻击特征字符串
  （如 `/etc/passwd`、`webhook.site`、`../`、`/bin/sh`、`~/.aws/credentials`、SQL/脚本注入样式）。恶意代码类论文的图注/正文最常踩。
  处理：把这些字面量软化成描述（"系统密码文件""某外部收集地址"），保留 API 名等无害词，重渲染重发。
  发前可自查：`grep -noE "/etc/[a-z]+|webhook\.site|\.\./|/bin/sh|/aws/credentials|<script" papers/<slug>/article.md`。
- 换封面：清掉 `publish.json` 的 `thumb_media_id`（保留 `draft_media_id`）再重跑发布，会重传封面并原地更新草稿。
- 换新机器：`bash scripts/setup.sh` 重装依赖并重建 `.claude/commands/paper.md` 薄壳。
